# 进行中的段不能靠整段变淡来表示

日期：2026-11-26

## 现象

进度卡的分段条里，已完成是实心主题色，未开始是空槽。进行中的那一段和空槽用的是同一条底轨，只把整段透明度在 1 和 0.55 之间呼吸。6pt 高的空槽本身就很淡，呼吸之后更接近「还没开始」，看不出哪一段正在做。当前任务行左侧是一颗 5pt 的圆点，同样只在变淡，任务名换行时也不像「这一条正在跑」。

## 现行行为

三种段态分开画，都在 `NotchTodoView.segment`：

- **已完成 / 已取消**：整段实心主题色，不动画。
- **未开始**：只有玻璃底轨。
- **正在进行**：整段铺 `tint` 不透明度 0.42（静止时也能和空槽、实心段分开），再叠一条两端透明的高光，1.1 秒从左扫到右。高光用 `TimelineView` 的时间相位，收起再展开不会从 0 重播。只裁扫光自己，不裁父层液态玻璃。

当前任务行左侧换成 11pt 旋转弧线（0.9 秒一圈），和扫光是同一件事。还没有进行中项时退成空心圆点。「下一步」箭头和完成勾共用这一列宽度，正文对齐。

系统「减少动态效果」或应用内「减弱动态效果」打开时，扫光和转圈都停。进行中的段留下 0.42 的填色，弧线停在固定角度。

只有 `progress.current != nil` 且该段填充 < 1 才算进行中。没有进行中项时，段条上的「下一项」回退不再呼吸。

## 不要再做

不要用整段 `opacity` 呼吸当进行中指示。空槽变淡之后和未开始段更像，而且会把高光一起压暗。

不要用 `easeInOut` + `repeatForever` 做这段循环。两端会停住，也每次 `onAppear` 从头播。扫光和转圈都走时间相位。
